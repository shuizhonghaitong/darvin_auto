# Darwin 工作流

接收比赛 URL、独立产物目录、运行范围和外部操作授权。将阶段产物、实际命令及结果、证据来源和未验证事项保存在该目录；阶段之间传递文件路径，不依赖对话记忆。允许调用方指定已有阶段产物，但须检查其与当前比赛和交接要求一致，标明复用及原始证据，不能声称本次重新执行了该阶段。

1. T1：URL 输入调用 `$competition-intake`，传入原始 URL 和产物目录，获取可解析的 `competition_spec.json` 和来源证据；检查关键要求、未知项和冲突。已有 CompetitionSpec 输入则检查文件，不重复需求理解。
2. T2：调用 `$solution-planning`，传入 CompetitionSpec 和独立目录；检查 `solution_plan.json` 可解析，并记录方案依据、未知项及阻塞。旧的 solution-discovery 不再是主链路依赖。
3. T3：依据规格和方案实现或复用 Runnable Solution；记录入口、依赖、模型资源及校验、实际本地推理验证和结果。禁止把未验证的实现当作已通过。
4. T4：依据规格和已验证的 Runnable Solution 实现或复用服务，产出 ServiceArtifact、ServiceContract、启动说明和实际接口验证记录；核对协议、资源及预测结果，错误响应不得伪装成成功预测。
5. T5：依据服务交接制作或复用镜像，记录 ImageManifest、镜像标识及实际验证证据；核对镜像与服务、资源和目标平台的一致性。构建、推送和远端访问分别记录，不把本地存在等同于平台可拉取。
6. T6：核对 CompetitionSpec、ImageManifest 和提交参数，使用现有 Darwin CLI 做授权范围内的提交准备，记录命令、结果及未知项。只有调用方明确授权本次真实提交后才能推送或提交；提交后记录 SubmissionReceipt、提交 ID、模型应用 ID、任务 ID 及实际状态。状态不明先只读查询，不盲目重复提交。

默认仅执行调用方授权的范围。Dry Run 到提交准备为止：不执行 Darwin 提交，不推送正式镜像；允许检查和复用已有镜像与证据，并明确标记尚未验证的步骤。已有独立 T1/T2 或从 T3 交接进入 T4 的调用仍可限定在指定阶段，不能因此自动执行后续阶段。不得擅自训练、下载资源或开展未授权的外部写操作。

每阶段在进入下一阶段前检查必需输入、产物和实际验证证据。关键要求、资源或权限缺失、验证失败、工具失败或存在无法安全解决的冲突时停止，保留失败轨迹和已有产物，报告具体阻塞；不得以文件存在、Agent 自述或旧提交替代本次运行证据。最终汇报本次实际执行的阶段、复用的产物、未验证项、外部操作和下一步需要的授权。
